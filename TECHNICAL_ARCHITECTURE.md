## Blueprint ↔ C++ split

The template's Blueprints keep doing what they already do well. C++ adds the systems the GDD needs to be robust and replicated.

```
ACharacter
└── ATHCharacter (C++)            health, weapons, downed/revive, speed multipliers
    └── BP_FirstPersonCharacter   camera, movement input, interaction, flashlight, NV, footsteps (template)
        └── BP_Koda               MetaHuman body (the pawn the Demo map spawns)

AGameMode
└── ATHGameMode (C++)             default classes, friendly fire, team wipe -> restart
    └── BP_FirstPersonGameMode    DefaultPawn = BP_Koda (Demo map's override)
```

`ATHCharacter` intentionally creates **no camera, mesh or movement bindings** so it cannot clash with the template.

- Every third-party package (Fab, Epic samples, template, downloads) has a row in `THIRD_PARTY_ASSETS.csv`: source, creator, license, link, where it lives, whether it's used. Add the row when a pack is added; check licenses there before a release.
- New packs go in `ThirdParty/<Pack>`: import there, or after adding from Fab move the folder in the editor (drag it, then right-click the folder → Fix Up Redirectors). Fab updates re-download into the pack's original folder.
- Move content only inside the editor, never in Windows Explorer, and pick *Delete unreferenced redirectors* in Fix Up Redirectors. A few assets may fail to save at the old path ("Illegal reference to private object ... ThumbnailInfo"): their moved copy is fine, delete the stale old file once `content_verify.py` shows nothing refers to it. Then update hard-coded paths (`grep -r "/Game/"` in Source, Config, Scripts). Scripted moves (`cleanup_reorganize.py`) work for animations and plain assets but crashed the editor on Blueprints and maps; Python has no redirector fix-up (use the editor's, or `-run=ResavePackages -fixupredirects`).
- C++ refers to content by soft path (loaded at spawn / game start), never with `ConstructorHelpers` on movable content: assets held by a class default can't be moved in the editor.
- `Scripts/Tools/content_inventory.py` reports what the game uses per folder; `content_verify.py` lists leftover redirectors and missing references (the automated tests `TacticalHorror.Content.*` check the same on every run; see TESTING.md) (54 missing editor-preview references came broken with the template and packs: Characters/Heroes, FPSTemplate, ArchVis).
- Deleted in the cleanup (restore from git history if ever needed): MetaHumans, the UE template's Variant_Horror / FirstPerson / Input, the Fab copies of the M4 / G17 packs, the placeholder Rifle / Pistol / grenade launcher, the G17 importer leftovers, and the two packs' showcase maps.

## Systems

### Health — `UTHHealthComponent`
- Server-authoritative. Hooks the owner's `OnTakeAnyDamage`, so `ApplyDamage`/`ApplyPointDamage` from anything works.
- States: `Alive → Downed → Dead`. Downed starts a bleed-out timer (`BleedOutDuration`, default 30 s). `Revive()` restores `ReviveHealthFraction`.
- Downed only while another player is up to revive them (`HasTeammateWhoCanRevive`): playing solo, or the last one standing, a player at 0 health just dies (developer, 2026-11-11: no reason to be downed alone). The result is the same team wipe, without the wait.
- **Regeneration** (2026-11-12, developer: no healing items; CoD-style): `bRegenerates` (players; enemies pass false to `SetDefaults`). Every hit restarts a server timer: after `RegenDelay` (5 s) without damage, `RegenStep` heals `RegenRate` (5) a second in tenth-second steps up to full, so nearly dead to full takes about 20 s. Revived players heal the same way from their 30%. Health already replicates, so nothing extra for co-op; a heal is never a "hit" (`HandleHealthChanged` only reacts to losses).
- While downed: held crouched (`UTHCharacterMovementComponent::UpdateCharacterStateBeforeMovement` forces `bWantsToCrouch` from the replicated health state, on the owner and the server alike, so moves agree; the crouch key can't stand them up) and crawling at `DownedSpeedMultiplier` of the standing speed; weapons blocked (no firing, aiming or switching; crosshair and ammo hidden); the status screen. Revived, they stand up (`UnCrouch`).
- Damage while downed: an **enemy's** blow (an instigator that isn't a player) kills (developer, 2026-11-09: enemies finish off downed players); anything else (a teammate's stray shot) is ignored.
- Friendly fire is asked of `ATHGameMode::IsFriendlyFireEnabled()` (default off).
- When any player stops being Alive the GameMode checks `ATHGameState::AreAllPlayersIncapacitated()`; a team wipe sets phase `Failed` and `ServerTravel("?restart")` after `TeamWipeRestartDelay`.
- Enemies/props: set `bCanBeDowned = false` (`SetDefaults` in the owner's constructor; `ATHEnemyCharacter` does).

### Revive — `ATHCharacter`
- Hold **E** while looking at a downed teammate within `ReviveRange` for `ReviveDuration` (3 s). Server-timed; cancels if either player moves away or goes down.
- The revive action is created at runtime with `bConsumeInput = false`, so the template's Interact (also E) keeps working.
- `GetReviveProgress()` for a UI bar (not built yet).

### Weapons
- **`UTHWeaponData`** (Data Asset) — all tuning: damage, headshot multiplier, CS-style range falloff, RPM, fire modes, magazine/reserve, reload/equip time, accuracy model, recoil pattern, ADS, move speed, sounds/FX.
- **`ATHWeaponBase`** — hitscan behaviour. Blueprint subclasses (`BP_Weapon_Rifle`, `BP_Weapon_Pistol`) set mesh + data and can implement `On Fired`, `On Reload Started/Finished`, `On Equipped/Unequipped`, `On Fire Mode Changed`, and override `AttachToOwner`.
- **`UTHWeaponComponent`** — loadout spawn (server), switching (client-predicted), ADS (FOV lerp, replicated for movement speed; iron sights, below), weapon input.
- *Iron sights:* while aiming, `UTHWeaponComponent::UpdateAimSights` puts the first-person weapon back at its hip hold (`CameraHoldOffset`) every frame, finds its sight points (`UTHWeaponData::SightBone`, `RearSight`, `FrontSight`: mesh space at the reference pose, carried by the bone so animation still moves them) and turns and moves the weapon so the line from rear to front sight runs down the middle of the screen, blended by the aim amount. Bullets already go to the middle of the screen, so the sights show where they land. The rear sight stays as far from the eye as at the hip unless `AimSightDistance` is set. Live tuning: `th.SightTune`. Third person is unchanged.
- **`ATHHandFlashlight`** — a held item that isn't a gun (`IsFirearm()` false: no ammo readout, crosshair or ADS; left mouse switches the light). Given by `UTHWeaponComponent::GiveHandFlashlight` when the owning client sees the template character's `PickupFlashLight` flag turn true (`FlashlightPickupFlag`), added as the next slot (key 3) and inspected. Its own model components: first person in the arms' `hand_r_Flashlight` socket, third person in the body's `hand_r`; `UsesThirdPersonWeaponCopy()` false. One beam per machine, on the copy that machine sees.
- **Weapon light** — `UTHWeaponData` *Weapon Light* section (mesh, attach frame in the muzzle bone's space, lens offset, beam). `ATHWeaponBase` keeps a light model on both copies and one beam on the visible copy. On / unlocked state is replicated on `UTHWeaponComponent` (L, `ToggleWeaponLight`, `UnlockWeaponLight`). `ATHCharacter::PawnClientRestart` removes the template Blueprint's L key binding.

**Gunplay model (CS-inspired)**
- *Recoil:* a fixed, learnable per-shot pattern (`RecoilPattern`, degrees). `ViewKickFraction` of it moves the camera; the rest only moves bullets. Spray index resets after `RecoilResetDelay` without firing. Camera recovers at `ViewRecoveryRate` after firing stops.
- *Accuracy:* cone half-angle from standing/moving (scaled by speed)/air, + per-shot spray growth, × crouch and ADS multipliers. `bFirstShotAccurate` gives a perfect first shot when standing still.
- *Damage:* `Damage × RangeModifierPer10m^(distance/10m) × (HeadshotMultiplier if bone ∈ HeadBoneNames)`.

**Networking**
- Owning client fires instantly (effects, view kick, predicted ammo, predicted impact) → `ServerFire(origin, view rotation, spray index, shot number)` (reliable).
- Server validates: equipped, not reloading, ammo, fire rate (75% tolerance), unique increasing shot number, origin within `MaxOriginError` of the pawn's eyes, spray index within ±2 of its own. It then re-traces using the **same deterministic recoil + seeded spread** (`SpreadSeed` replicated once, hashed with shot number) and applies damage.
- Cosmetics to everyone else via unreliable multicast.
- Not done yet: lag compensation (rewinding targets). Fine for co-op vs AI; revisit if PvP or fast enemies show hit-reg complaints.

**Collision**: custom trace channel **`Weapon`** (`ECC_GameTraceChannel1`, default Block). `ATHCharacter` makes capsules ignore it and meshes block it, so hits report bone names. The horror template's full body (the one other players see) had collision off; `UTHWeaponComponent` turns on queries for the bullet channel only on that body (`bBodyBlocksBullets`, 2026-11-05, found by `Functional.ShotDamage`), and the server keeps its bones updated even when nobody looks at it. `ATHEnemyCharacter` does the same.

**Input**: if `WeaponMappingContext` is empty the component builds one at runtime — LMB fire, RMB aim, R reload, 1/2/3 slots, wheel cycle, B fire mode — at priority 1, above the template's `IMC_Default`. That makes RMB aim instead of the template's camera zoom while a weapon is held. Replace with real `IA_*`/`IMC_*` assets whenever you like (assign them on the component in `BP_FirstPersonCharacter`).

**Shell casings**: `PlayFireEffects` (so on every machine that sees the shot, never the dedicated server) spawns an `ATHShellCasing` at the muzzle + `ShellEjectOffset` (aim space). Not replicated. Its physics body is its own capsule sized from the mesh bounds, so it doesn't rely on the mesh's collision (the casing meshes have none). Physics-only collision (bullets and interaction traces ignore it), passes through pawns, CCD on, a low-bounce / high-friction physical material and strong angular damping so it settles where it lands, one bounce sound on first impact, `ShellLifetime` and `MaxShellCasings` per weapon. All settings are in the *Shell Casing* section of the weapon data.

**What other players see (third person)**
- Each weapon has two copies of its mesh. `Mesh` is the first-person viewmodel (arms included) on the owner's camera, *Only Owner See*. `ThirdPersonMesh` is the same mesh with the arm material slots hidden (`ThirdPersonHiddenMaterialSlots`) and the spare magazine bone hidden (`ThirdPersonHiddenBones`; G17: `Mag1`), holding frame 0 of the idle animation, *Owner No See*. It is attached to the body's `hand_r` and placed every frame after the body has animated.
- Placement: the weapon is placed from the head, not the hand: its `ThirdPersonGripBone` (the rig's own right hand) goes to `ThirdPersonAnchorBone` (`head`) + `ThirdPersonAnchorOffset` in aim space, with the barrel along the body's facing and aim pitch. So the rifle's stock stays in the shoulder and the sights at the eye whatever the source animation's arms do (the rifle animations are female, on a male body). Rifle `(18, 5, -12)`, pistol `(40, 2, -14)`, set by `setup_body_anims.py`. `ThirdPersonRotationOffset` tilts it.
- Hand IK: the weapon gives the body animation (`FTHWeaponGrip`, renewed every frame) the anchor and where the rig's own hands are relative to the grip. The body solves a two-bone IK for each arm onto those points, using the same formula on the worker thread so the hands land on the grips, with the elbow pole forced down and slightly out. With `bThirdPersonMatchRigHands` (default) each hand copies the rig's hand (`FTHHandShape`): a palm frame (X wrist → middle knuckle, Y pinky → index knuckle) and knuckle centre are built from finger bones found by name below each hand bone (`FTHHandShape::FindFingers`, metacarpals skipped) on both skeletons, the body hand bone is placed and turned so its frame matches the rig's, then each finger joint is turned the least amount to point like the rig's. This works across skeletons with different bone axes and hand sizes (the rig's hands are larger, hence matching at the knuckles). `ThirdPersonRightHandOffset` / `ThirdPersonLeftHandOffset` nudge the hands without moving the weapon; `ThirdPersonRight/LeftHandRotation` turn them about the aim axes. Without rig hands, the hands go to the rig's hand bones at the animation's angle. `bThirdPersonLeftHandFollowsRight` keeps the animation's left hand relative to the right instead (unused now). The body set's *Hand Pose* (an animation + frame) replaces the finger bones first; matched rig fingers override it. `th.ThirdPersonTune` adds to all of these live in play, for tuning.
- Lowered carry: a body set's `LoweredSet` is played instead while the weapon isn't ready. `UTHBodyAnimInstance` keeps a `ReadyAlpha` (1 = up) from replicated `IsAiming()` and `RaiseWeapon()` (called by `ATHWeaponBase` on every shot it shows, so every machine agrees), held for `ReadyHoldTime` after the last of them. Idle and walk weights are split between the two sets by `ReadyAlpha` (one shared walk phase), the aim offset and hand IK are scaled by it, and Upper Body Yaw blends between the sets. With the IK off, the weapon is placed so the rig's right palm (knuckle centre and facing, `FTHHandShape`) matches the body's right palm, so it sits in the lowered animation's hand from the first frame.
- During full-pose actions (reload, equip, fire) the IK fades out and the weapon blends onto the right hand at the offset recorded while the hands were on it, so it follows the reload and recoil; afterwards it blends back to the anchor.
- Muzzle flash, shell casings and the shot sound come from whichever copy this machine shows (`GetVisibleMesh`).
- The body is the template's extra `SkeletalMesh` component (ACharacter's own `Mesh` is empty); `UTHWeaponComponent::GetBodyMesh()` finds it. At BeginPlay the weapon component replaces its Anim Blueprint (`ABP_Manny`) with **`UTHBodyAnimInstance`** (`BodyAnimClass`; clear it to get `ABP_Manny` back).
- `UTHBodyAnimInstance` is pure C++ (native pose evaluation, no Anim Blueprint). Legs: idle / four-way walk / crouch blended by velocity direction, speed-matched play rate, shared phase. Upper body (from `spine_01`): the held weapon's aiming pose in mesh-space rotation, so the torso stays on target while walking. Then the pitch aim offset, then actions: fire is additive, reload and equip replace the upper body and are stretched to `ReloadDuration` / `EquipDuration`. It reads only replicated state (velocity, crouch, aim pitch, current weapon, reload), and actions are started where the weapon already plays effects for everyone.
- What to play: `UTHBodyAnimSet` data assets in `Content/Characters/BodyAnimSets`. Any slot a weapon's set leaves empty falls back to `DA_Body_Unarmed` (on the weapon component: Lyra UE5 male walk / crouch). When legs come from the unarmed set, the weapon set's `UpperBodyPose` is layered on the upper body, weighted by that share. `DA_Body_Rifle` uses the SampleAnimationPack's aiming idle and walks (full body), with the unarmed crouch plus layering. `DA_Body_Pistol` uses the unarmed legs plus the UE5 template's `MF_Pistol_Idle_ADS`. Both use Lyra fire / reload / equip. Walk play rate is matched to speed from each clip's root motion (`WalkAnimSpeed` / `CrouchAnimSpeed` override it), within `PlayRateRange`. Built by `Scripts/Tools/setup_body_anims.py`.
- `ATHCharacter::OnStartCrouch/OnEndCrouch` move that body up/down with the capsule (ACharacter only does this for its own `Mesh`).
- Look at it alone: `th.ThirdPerson 1` views your own character from outside, `0` goes back; `th.ThirdPersonView` places the camera (see Scripts/Tools/README.md).

**Movement speed**: `UTHCharacterMovementComponent::GetMaxSpeed()` multiplies whatever the Blueprint sets (walk/sprint/crouch) by the weapon/ADS/downed multiplier.

### Navigation
- The project's navigation voxels are 10 cm (`Config/DefaultEngine.ini`, RecastNavMesh), not the default 19: navigation keeps an agent's radius (35 cm) from walls, rounded up to whole voxels, and the default closed the range kit's 106 cm doorways.
- Navigation only sees simple collision. The range kit's pieces (floors, walls, crates) only have complex collision, so levels built from them need invisible boxes for navigation (`build_enemy_test_map.py` adds them).
- `L_EnemyTest`'s navigation mesh is static, built by its script and saved with the level; a full rebuild while playing took over 20 s. Use Dynamic for levels with doors or moving obstacles.
- Editor-only script helpers in C++: `Debug/UTHEditorScriptLibrary` (shape a volume's box brush, build navigation and probe it).

### Bullet holes — `UTHImpactSurfaces`
One shared data asset, `DA_ImpactSurfaces` (`UTHWeaponData::ImpactSurfaces`), maps a hit's surface type (from the hit material's Physical Material) to a list of decals; each shot picks one at random, sized by the weapon's `ImpactDecalSize`. The server's trace finds the surface and sends it in `MulticastShotEffects`, so every machine draws the same set; a client's predicted hole uses its own trace. Surfaces without their own set use Default. Surface types (Project Settings, Physics): Concrete, Dirt, Wood, Metal, Plaster, Paper. Physical Materials: `PM_Concrete`, `PM_Wood`, `PM_Dirt` (template, `Template/LevelPrototyping/PhysicMAT`) and `PM_Metal`, `PM_Plaster`, `PM_Paper` (`Effects/PhysicalMaterials`). To tag a surface: set the Physical Material on its material (every mesh using it), or *Phys Material Override* under Collision on one placed actor (bullets trace simple collision, which the override covers). Physical Materials also pick footstep sounds. In `L_FiringRange` only the targets are tagged (Paper, by `tag_range_surfaces.py`); everything else is Default, concrete holes.

**Blood** (2026-11-09): surface type **Flesh** (`PM_Flesh`), set on every bone of a body from C++ (`ATHEnemyCharacter::FleshMaterial`; players' bodies through `UTHWeaponComponent::BodyPhysicalMaterial`, so friendly fire bleeds too). Each surface's entry (`FTHSurfaceImpact`) can also have `Effect` (particles at the hit, out of the surface; replaces the gun's `ImpactEffect`), `ExitEffect` (along the shot) and `SplatterDecals` (a decal on whatever the shot would reach behind the hit, within `SplatterDistance`, the body itself skipped; bigger the further it lands). Flesh: no bullet hole, Yarrawah Interactive's rifle entrance and exit wound effects (CPU versions: their droplets collide with the world; `EffectParameters` sets their own controls on spawn: `EmitterDurationCoefficient` 0.25, `ParticleLifeTimeCoefficient` 0.35, `ParticleAmountCoefficient` 0.6, `GravityCoefficient` 1.5, because the spray as authored lasted too long and was a lot; and `EffectCollisionChannel` sets their `CollisionChannel` to **BloodDroplets** (`ECC_GameTraceChannel2`, DefaultEngine.ini): on their own WorldStatic the droplets landed on living bodies' invisible capsules and hung in the air, and the capsules of enemies and players ignore BloodDroplets, while walls, floors and corpses block it. That parameter is an enum, which `SetVariableInt` doesn't reach, so `UTHImpactSurfaces::SetEffectCollisionChannel` finds it by name), the small blood splatters from the animated blood decals pack (single, not animated, versions). The shot direction is taken from the shooter's eyes to the hit on each machine, so it isn't sent. **Sounds** (High Impact Media's Bullet SFX - Flesh): each machine traces a few cm around the hit to find the body and bone there, then plays a player's-body sound if it's an `ATHCharacter` (`PlayerHitSounds`, *Character Hit*: friendly fire), else the surface's `HeadshotSounds` on a head bone (*Guts*), else its `Sounds` (*Flesh*), else the gun's `ImpactSound`; through `SoundAttenuation` (`/Game/Audio/SA_BulletImpact`, full volume to 3 m, silent 35 m beyond), at Gunplay volume. A kill is only known on the server, so the enemy plays its own `KillSounds` (*Guts*) from the hit bone when its death arrives, on every machine (not for headshot kills, which already sound like one, and not for a late joiner finding a corpse). Set up by `setup_impact_decals.py`. A surface listed with no decals gets no hole (it no longer falls back to Default).

### Enemies — `ATHEnemyCharacter`
- Quick reference for designers (each type, every setting and its current value): **ENEMIES.md**.
- A `ACharacter` with `UTHHealthComponent` (**200** health, twice a player's, developer 2026-11-10; no downed state). Bullets pass its capsule (ignores the Weapon channel) and hit the body's physics asset bodies (query only, Weapon channel only), so `HeadBoneNames` headshots work; the server ticks its bones even unseen. The M4 (about 33 at range) takes 7 body shots or 2 headshots. The capsule also ignores **BloodDroplets** (below).
- The body comes from the Blueprint: `BodyMesh`, `PhysicsAssetOverride` (for meshes without a suitable one), `Animations` (a `UTHEnemyAnimSet`). UE4-mannequin-style bodies: mesh at Z -90, yaw -90 in a 34 x 90 capsule.
- **Random looks** (2026-11-11, developer: the three hall zombies looked the same; more variety in real levels): `Appearance` (a `UTHEnemyAppearance`: looks, each with bodies, material choices by slot name, and outfit parts whose choices are sets of meshes sharing one material pick so pieces match). The server picks `AppearanceSeed` at `BeginPlay` (replicated, initial only); every machine builds the same look from it with an `FRandomStream`: body mesh (and physics asset), materials, and clothing and hair as extra `USkeletalMeshComponent`s following the body (`SetLeaderPoseComponent`, so also its ragdoll; no collision: the body takes the shots). `BP_Zombie` uses `DA_ZombieLooks` (M04, M02, F02; ENEMIES.md); the line-up clears it. F02 gets M02's physics asset: her own (`PHYS_Zombie_F02_NoBreasts`) has collision disabled on the spine, upper arms and hair bodies, so shots passed through her torso.
- **Mixamo clips that travel, poses with no get-up, waiting vs playing dead** (2026-11-14, developer). `UTHEnemyAnimSet::WalkTravel`: a walk whose pelvis moves under its root (Mixamo's Zombie Crawl, 2 m a loop) is held in place: each sample carries a `Shift` (it replaced the bed-clip `Lower`), the pelvis moved back by Travel x (time / length) (`setup_enemies.py` `pelvis_travel`; Walk Anim Speed = travel / length). A lying pose with no Get Up clip (a siren standing or sitting in wait) eases out: phase 3 lasts while `DownFade` fades and `StumbleAlpha` follows it, so the pose blends into its moves. Whether one waits lying (`ATHEnemyAIController::bWaitsLying`, on `ApplyBehavior`): the placed enemy's `ATHEnemyCharacter::WaitPose` (As Behaviour / Lying / Standing), else an actor tag `Lying` / `Standing`, else `bLiesDown` and a roll under `LiesDownChance` (DA_Ambusher 0.6). `DA_AmbusherLooks`: DA_ZombieLooks' looks (with the Priest, M09) plus Hazmat, Police and Construction (no limb pieces). `FTHEnemyLyingPose::bPlayingDeadOnly`: `LieDown(.., bPlayingDead)` picks among the poses that match (the siren's play-dead drop), else any. Footsteps: `UTHEnemyAppearance::FootstepSounds` (a mutant's stomp) set on the footstep component as `SetStepSoundOverride` in `ApplyAppearance`, on every machine (the look is replicated, the behaviour isn't). Sounds: `UTHEnemyBehavior::ScreamSounds` (the chase-start alert of a behaviour with a Scream Radius), `DoorSlamSounds` (a charger: `UTHDoorSyncComponent::HandleRequest` now returns whether the door will move; once a door, `ATHEnemyCharacter::PlayCrashAt`), `ATHEnemyCharacter::HeadSeverSounds`; an ambusher's Alert Sounds play as it springs itself (`ThinkAmbusher`, `NotifyDamaged`), not for the pack `AlertPack` wakes, and not at the chase start. The player's flicker (`ATHCharacter::UpdateLightFlicker`): `FlickerSteadyTime` (0.6-1.6 s, shorter the nearer) then a dip of `FlickerDipTime` (0.12-0.35 s; it used to change every 0.04-0.18 s), `FlickerSounds` at the view as it dips (locally, at most every `FlickerSoundGap`).
- **Three fixes from the enemy code review** (2026-11-14). `Hook` refuses a downed player and the unaware stalker's loop goes on to the next one (it hooked and let go of a downed quarry every tick, never stalking the teammate still up). `UTHEnemyBehavior::InvestigateGiveUpTime` (20 s): `Investigate` drops a noise not reached by then (`NoiseTime` was written and never read, so a hunter banged on a closed door for good). `bCalledIn`, set by `HearCall` and cleared when that chase ends: a called hunter (another's scream, or the director's `Summon`) starts its chase with Alert Sounds and doesn't `CallOthers`, so a scream reaches Scream Radius and no further. What the review found and didn't change: ENEMY_PLAYTESTS.md.

### First-person weapons and walls
- The first-person weapon (with its arms), its muzzle-flash quads and light model are first-person primitives for the local player (`ATHWeaponBase::UpdateFirstPersonRendering`). `UTHWeaponComponent` turns on the view camera's **First Person Scale** (`FirstPersonScale`, 0.25): the engine draws those primitives shrunk toward the eye by that much in the vertex shader (through the materials' first-person output), so they look the same on screen but stay in front of a wall the player walks into. Their real transforms are unchanged (bullets, sights and the iron-sights test don't see it). Walls still hide what is really behind them: the weapon light and muzzle flash come from the real muzzle position, which can be inside a wall.

### Look sensitivity — `UTHControlsSettingsSubsystem`
- Look sensitivity (0.02–3, default 1) scales all turning; aim sensitivity (0.02–3, default 1) multiplies it further while aiming down sights, blended by `UTHWeaponComponent::GetAimAlpha`. Applied in `ATHPlayerController::AddYawInput` / `AddPitchInput`, so the pawn's look bindings need no change. GameUserSettings.ini, saved when the settings panel closes; local only. The settings panel's Controls section has the two sliders and the converter.
- One look sensitivity unit = `DegreesPerCount` 0.175° per mouse count: mouse axis sensitivity 0.07 (DefaultInput.ini `AxisConfig`) × the legacy yaw / pitch scale 2.5 (`bEnableLegacyInputScales`). The same slow or fast, and while aimed (the engine's `bEnableFOVScaling` doesn't reach the Enhanced Input look). Engine mouse smoothing is off (`bEnableMouseSmoothing=False`; developer 2026-11-12: a converted CS2 sensitivity was unplayably slow): `UPlayerInput::SmoothMouse` scales a frame's movement by frame time ÷ (sampling time × samples), so a 1000 Hz mouse, about 8 samples a frame, turned about an eighth as far; the test had sent 1 sample a frame and missed it. Changing either input setting changes every player's feel and the converter: update `DegreesPerCount`; `Functional.MouseTurn` fails until it matches.
- Converter: `GetOtherGames()` lists games with their published degrees per count at sensitivity 1 (Source games 0.022, Valorant 0.07, Overwatch 2 and Call of Duty 0.0066). Ours = theirs × their degrees ÷ 0.175, for the same mouse DPI; hip fire only. Fortnite, Rainbow Six Siege, PUBG and Battlefield use other formulas and aren't listed.

## Conventions
- C++ classes `TH` prefix; Blueprints `BP_`, data assets `DA_`, input `IA_`/`IMC_`, widgets `WBP_`.
- New gameplay systems = C++ component or subsystem + Blueprint/data configuration. No giant classes.
- Server authority for damage, AI, objectives, important interactions. Every replicated feature gets a 2-player PIE test.
- Data Assets for tuning. Don't hardcode weapon/mission numbers in code.
- New C++ content folders go under `Content/` by feature (`Weapons/`, `Missions/`, `AI/`...). The template's folders (`Blueprint/`, `Interaction/`...) stay as they are.

## Doors in co-op

The template's doors run only on the machine whose player pressed interact. `UTHDoorSyncComponent` (on `BP_Door`, `BP_Outward_Door`, `BP_SlideDoor`; added by `Scripts/Tools/setup_door_replication.py`) keeps their Blueprint logic and adds a replicated open / closed state owned by the server. Every machine runs the door's own `Interact` event to reach that state, so each plays the same animation and sound. A client's press moves its door at once and asks the server through `ATHCharacter::ServerRequestDoor`; the server checks the distance, and a refused press is undone. New interactive template doors need the component too. `BP_KeypadDoor` uses the same component, which also shares `CodeCorrect?`: one player's code unlocks the door for everyone.

`BP_DoorLock`, `BP_Key` and `BP_ValveDoor` read input on one machine from an overlap any pawn can trigger, and the lock's state is in a Flip Flop that can't be replayed, so they work differently. Components derived from `UTHPressableComponent` (`UTHLockedDoorComponent`, `UTHKeyPickupComponent`, `UTHValveDoorComponent`) turn that overlap off and take the press from `ATHCharacter` (`IA_Interact`, or F for the valve), which asks the server. The server decides and replicates the result; each machine plays the Blueprint's own timelines. Rules: only a player with a key unlocks a `BP_DoorLock`, then anyone can use it; anyone can turn a valve. A valve's prompt shows only on its wheel: `UTHValveDoorComponent` makes the rest of `BP_ValveDoor` ignore the Visibility channel the interact trace uses (bullets use the Weapon channel and still hit it). Button prompt text comes from each actor's `GetButtonPromptInfo` (My Blueprint, Interfaces); only its Action is shown, the F is part of the prompt widget. `Has Key?` stays the template's one flag, so a key fits any lock and a player can carry only one. A taken key is hidden with its collision off, and comes back where it was if its holder's pawn is destroyed, which is what a player leaving does. Unlocking a door uses the key up: the holder's flag is cleared and the key actor destroyed, so each key opens one lock.

## Director and the test facility (2026-11-13)

`ATHDirector` (Core/THDirector), placed once in a level, runs on the server every 0.25 s. **Intensity** (0..1) rises with
damage players take (`PerDamage` a point), shots they fire (`PerShot`, from `ATHWeaponBase::GetLastServerShotTime`) and
enemies going for someone (`IsAggressive`) within `NearDistance` of a player (`PerAggressiveEnemy` a second), and falls by
`Decay` a second. **Phases:** Calm (below `CalmBelow`): after `CalmBeforeWave` it brings a wave; Active; Relax (at
`PeakAbove`): `RelaxTime` with no waves, and every enemy controller gets `HoldOff` (a stalker's strikes, openings and lures
pushed back). A **wave** (`SpawnWave`): one of `Waves` by weight (behaviour, count), `EnemyClass` spawned round an
`ATHSpawnPoint` out of every player's sight (a trace to each player's eyes) `SpawnDistance` from the nearest, at most
`MaxAlive` enemies alive in the level; hunters get `Summon` (they know where the nearest player is and come). Tuning:
`UTHDirectorSettings` (`DA_Director`, `setup_director.py`). `th.Director.Debug 1` shows intensity and phase on screen.

`L_TestFacility` (`build_test_facility.py`): a generic test facility (map design comes later; developer). The automated
tests stay on `L_EnemyTest`, whose hall they rely on. Its unlocked doors (template `BP_Door`) don't affect navigation
(`setup_door_replication.py` clears their parts' `CanEverAffectNavigation`), so enemies path through them; the stalker opens them (`OpenDoorsAhead`), the charger slams them, hunters and ambushers bang on a closed one, the siren stops at it; the locked `BP_DoorLock` does, and the navigation mesh is static, so enemies can't path into the storage room even after a player uses `BP_Key` (known, 2026-11-13).

**Light and dark in what enemies see** (2026-11-13). `UTHLightingSubsystem::GetLightOn(Player)` (a world subsystem,
cached 0.25 s a player): 1 with any light the player or their attached actors carry shining; else the best of the level's
local lights (not carried by a pawn, listed every 5 s): 1 - distance / attenuation radius, inside a spot's outer cone,
with a clear WorldStatic/WorldDynamic line from the lamp. `ATHEnemyAIController::IsVisible` = in its perceived view
(`FKnownPlayer::bVisible`) and `CanMakeOut`: within the behaviour's `DarkSightDistance`, or lit (`LitAbove`, 0.3), or no
dark sight set. `PickTarget` refreshes a made-out player's location every think (walking into the light while in view
counts), and a player perceived but not made out isn't remembered as seen.
